## Dependency notes

- The chain is strictly linear by design — the spec mandates the ordering
  ("Do not build AI first" §35; "Do not start AI retrieval until the evidence
  is structured" §35 Phase 3; voice "only when Phases 1–7 are stable" §35
  Phase 8). Do not parallelize across plans; parallelize within them.
- 005's anchor validation depends on 004's exact anchor slugs — renaming an
  anchor after 004 lands breaks the evidence index and AI deep links.
- 006 reserves (but must not implement) `compare_job_description`; 007 fills it.
- First-launch scope (spec §36) = Plans 001–008. Plan 009 is explicitly
  post-launch.

## Accounts & infrastructure

- **Vercel** (operator has an account): deployment target (Plan 008), env-var
  home for `OPENAI_API_KEY` / `OPENAI_MODEL` / `NEXT_PUBLIC_SITE_URL`, Vercel
  Analytics. The operator enters all credentials themselves — no plan handles
  secret values.
- **Supabase** (operator has an account): **intentionally unused in V1.**
  Spec §3 forbids a database/CMS/auth "unless needed" and §37 lists
  database-backed features as out of scope. Supabase appears in the Offboard
  case study only as *described product architecture*. If a future feature
  genuinely needs persistence (e.g. conversation analytics with a designed
  privacy approach, spec §30), that's a new plan.
- **OpenAI API key**: required from Plan 006 onward for live behavior; all
  test suites are designed to pass keyless (mocked) so CI never needs it.

## Open design question

- **A strategy-session mockup shows a richer 3-panel layout** than what is
  built — right rail in use on the homepage, nav icons, a generative-UI card
  inside the AI thread, voice controls. Captured as
  [010-visual-reconciliation.md](010-visual-reconciliation.md), which also
  records that the mockup **misstates what Offboard is** (it shows an IT
  offboarding tool; Offboard is a job-search product per spec §11/§13 and the
  live product site). The built case study is correct; the mockup is not.

## Findings considered and rejected

- **Use Supabase for the evidence index / chat history**: rejected — spec §3
  mandates a repo-owned curated index and no V1 database; deterministic local
  search is a feature (transparency), not a limitation.
- **Vector database / embeddings for retrieval**: rejected for V1 — spec §17
  explicitly defers it; the `searchEvidence` signature is the stable seam for
  adding it later.
- **Build voice alongside text mode**: rejected — spec §23/§35 sequence voice
  after a stable text experience; realtime infra would destabilize launch.
- **Dark mode in launch scope**: rejected — spec §6/§37: only after light
  theme is polished.
